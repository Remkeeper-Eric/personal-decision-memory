# 发布与隐私

## 发布的内容

源码、Skill 模板、文档、合成示例及测试夹具采用 [MIT](../LICENSE) 许可。MIT 的标准文本参考 [Open Source Initiative](https://opensource.org/license/mit)。作者的真实个人库和原始会话不随源码分发。

代码许可不意味着需要公开你自己的决策记录。每个使用者在本机 init 自己的空库，并自行决定经验内容、范围及是否批准。

## 本地数据位置

- vault/：正式记录历史、候选、批准清单和派生索引。
- runtime/：审核会话、本机日志、配置备份、备份归档和本地验证产物。
- testing/runs/：原始实验提示、返回、模拟批准清单和会话输出。
- verification/：开发期本机验证报告。

这些目录都由 .gitignore 排除。安装脚本会备份使用者原有配置，因此安装备份可能包含与本项目无关的秘密；不要公开它们。

自定义 --vault 或备份位置后，默认忽略规则不一定覆盖新位置。请检查实际上传清单，不能只凭“设置了私有仓库”就把所有运行文件提交进去。备份应独立存放，源码仓库不能替代个人库备份。

## 生成可审阅的源码包

```powershell
.\.venv\Scripts\python.exe scripts/prepare_release.py --check
.\.venv\Scripts\python.exe scripts/prepare_release.py
```

脚本按明确的源码目录和文件白名单收集，跳过测试运行目录、真实库、虚拟环境、Git 状态及其他私有目录。它拒绝源码符号链接，并对常见凭据格式和固定 Windows 用户路径做检查；错误只列文件名，不回显可能的秘密。

输出在 dist/：源码 ZIP、SHA256 文件，包内有 RELEASE-MANIFEST.json 列出相对路径及每个文件的哈希。ZIP 用于给使用者下载，也可作为上传前待审阅的文件范围；脚本不提交 Git、不创建仓库、不上传 GitHub。模式检查不能发现一切私人信息，仍需查看文件清单和内容。

上传已有工作目录时，还需核对 git status 和待提交 diff；.gitignore 不会自动撤销曾经跟踪过的敏感文件。首次提交前尤其应排除真实库、会话令牌和个人测试日志。发布脚本生成的 ZIP 不包含 .git 历史。

## 报告问题与贡献

公开 issue 只提供复现步骤、版本、错误类型和明确标为合成的数据。不要贴整个 vault、Codex 配置、审核 URL、原始聊天或安装备份。若需要真实案例，先由使用者选定并脱敏，不自动扫描和导入。

## 测试证据的发布方式

公开文档保留工程与行为实验的摘要和已知失败；原始测试会话留在开发者本机。文档中用等宽文字注明的 testing/runs 路径是本地证据索引，源码包里不包含这些路径，不能将缺失原始日志伪装成可公开复核的完整证据。

合成测试通过不是“训练成作者本人”的证明。项目不修改模型权重，实际个人化收益需要使用者在新任务中评价；模型服务仍可能处理被检索到的内容。
