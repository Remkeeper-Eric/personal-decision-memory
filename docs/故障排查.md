# 故障排查

先在仓库根目录使用 .venv 内的 Python，避免调用到另一份环境。以下检查不需要模型 API Key，也不会批准记忆。

## Python 或依赖找不到

确认 Python 3.12 可用，再按 README 重建环境并安装 requirements.lock.txt、执行可编辑安装。不要只安装第三方同名包。若包源没有锁定版本，保留错误信息核对包源；不要擅自升级全部依赖后宣称与已验证版本相同。

## 库未初始化

doctor 报正式清单不可用时，先确认 --vault 是否指向预期库。全新空库可运行 init；已有记录却丢失清单时应从可靠备份恢复，不能扫描正文重建批准状态。

## SQLite 不支持 FTS5/trigram

在 PowerShell 中用多行写法检查版本及创建能力：

```powershell
@'
import sqlite3
c = sqlite3.connect(':memory:')
c.execute("CREATE VIRTUAL TABLE t USING fts5(text, tokenize='trigram')")
print(sqlite3.sqlite_version)
'@ | .\.venv\Scripts\python.exe -
```

若报没有 fts5 模块或 trigram tokenizer，请换用包含相应 SQLite 功能的 Python 3.12 发行版后重建环境。这与正文批准或模型能力无关。

## Codex 看不到 MCP 或调用挂起

先运行本地 doctor，再检查安装预览、注册和当前会话是否重新加载。安装脚本 --apply 会创建所配置的临时目录。服务只需本机子进程通信；如果宿主沙箱阻止它，应在允许该本机调用的环境重试，不换用真实库执行合成测试。

不要无限重试同一调用。保留失败类型、时间、Python 版本和脱敏后的参数；不能根据超时猜测“没有相关记忆”。

## 对话批准保存失败

先核对安装目录、中央库和已展示版本的 sha256、vault_id。内容指纹不符、正式版本已变化或库不一致时，不更新指纹强行重试；重新展示实际内容并取得用户批准。缺少 --confirmed 或确认原话时，命令不会保存；这些参数仍不能代替真实用户授权。新会话若还要求打开页面，应核对已安装的 Skill 和 AGENTS 受管区块是否已更新。

## 旧审核页打不开（非必需）

当前默认是对话内审核，不需要页面。以下仅用于选择保留旧入口的使用者。

默认库使用 scripts/打开审核页面.ps1；它会创建 runtime/。检查 runtime/review-error.log，但不要公开带随机路径的审核 URL 或会话文件。自定义库需使用显式 --vault 的 review 命令。

候选修改后原确认失效属于预期保护。重新加载并阅读新版本后才能确认，不能通过改批准清单绕过。

## 已有记录却检索不到

核对是否正式有效、项目名是否稳定匹配、环境标签是否齐全、正文指纹是否有效，以及措辞是否超出现有检索能力。首次无结果可换一次关键词，仍无结果就如实说明。

contexts 中的 omitted 不是不存在；需要时用 get_memory 补取。外部文章不是个人偏好，相关性分数也不是可信度。

## 索引损坏

先停止相关 MCP 与审核进程，再针对正确库运行 doctor --rebuild。正式清单或正文指纹损坏不能仅重建索引修复，应从备份恢复或重新生成修订候选并审核。
